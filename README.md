# Интерфейс обмена текстовыми сообщениями через GREEN-API

## Возможности

- Подключение инстанса GREEN-API по `idInstance` и `apiTokenInstance` (сохраняются в браузере).
- Создание чата по номеру телефона получателя через `CheckAccount`.
- Отправка текстовых сообщений через `SendMessage` с оптимистичным обновлением интерфейса.
- Получение входящих сообщений через HTTP API: `ReceiveNotification` + `DeleteNotification`.
- Отображение статусов отправки, счётчиков непрочитанных, группировки сообщений по дням.
- Светлая и тёмная тема, адаптивная вёрстка, работа с клавиатуры.

Только текстовые сообщения — как и требуется в задании.

## Как проверить вручную

1. Зарегистрируйтесь в [личном кабинете GREEN-API](https://console.green-api.com) на тарифе
   «Разработчик» (бесплатный, 3 чата) и создайте инстанс.
2. Авторизуйте инстанс по QR-коду: в MAX откройте «Профиль → Устройства → Войти по QR-коду».
   Пароль на вход в мессенджер при этом должен быть отключён.
3. Скопируйте `idInstance` и `apiTokenInstance` из кабинета и введите их в приложении.
   Если в кабинете указан индивидуальный `apiUrl`, раскройте поле «Показать адрес API».
4. Нажмите «Новый чат», введите номер телефона второго абонента MAX и отправьте сообщение.
5. Ответьте из приложения MAX — он появится в переписке автоматически.

### Важно: настройки инстанса

**У нового инстанса все настройки получения уведомлений выключены по умолчанию.** Без
`incomingWebhook` входящие сообщения не попадают в очередь, и `ReceiveNotification`
бесконечно возвращает пустоту: сообщения уходят, но не приходят. Поле `webhookUrl` при этом
должно быть пустым — иначе метод вообще не работает.

Приложение проверяет настройки через `GetSettings` при подключении:

- если что-то выключено, показывается красный баннер с описанием проблемы;
- кнопка «Включить и очистить очередь» вызывает `SetSettings` и включает нужные
  переключатели (`incomingWebhook`, `outgoingWebhook`, `outgoingMessageWebhook`,
  `outgoingAPIMessageWebhook`, `stateWebhook`) и очищает `webhookUrl`;
- **GREEN-API перезапускает инстанс и применяет настройки в течение 5 минут** — до этого
  входящие сообщения не появятся;
- пока настройки не в порядке, цикл опроса не запускается, чтобы не делать вид, что
  всё работает.

Блок «Диагностика приёма» в интерфейсе показывает состояние инстанса, статус опроса,
значения переключателей и **сырое тело последнего уведомления** — с его помощью можно
сразу понять, доходит ли событие до браузера.

Номер телефона должен принадлежать РФ (11 цифр, код 7) или РБ (12 цифр, код 375): такие
номера принимает метод `CheckAccount`.

## Архитектура

```
src/
  api/
    greenApi.ts    клиент HTTP API: адреса методов, таймауты, отмена запросов
    webhooks.ts    разбор уведомлений GREEN-API в события приложения
    errors.ts      GreenApiError и извлечение текста ошибок из ответа
    types.ts       типы форматов API
    index.ts       публичный экспорт слоя api
  hooks/
    useSession.ts          учётные данные инстанса
    useMaxChat.ts          привязка интерфейса к API: отправка, поиск чата, опрос
    useNotificationLoop.ts цикл ReceiveNotification / DeleteNotification
    useChatLog.ts          состояние чатов и сообщений, localStorage
  store/
    chatReducer.ts  чистые переходы состояния (покрыты тестами)
  components/      экраны и элементы интерфейса
  utils/           телефоны, даты, текст, localStorage
  model.ts         доменные типы: Chat, Message, MessageStatus
```

`model.ts` не зависит от слоя `api`: тип статуса сообщения объявлен в домене, а не в
разборе вебхуков. Наружу слоя `api` смотрит только `api/index.ts`.

`App` рендерит `ChatScreen` с `key={credentials.idInstance}`, поэтому при смене инстанса
состояние чатов, опрос уведомлений и таймеры пересоздаются целиком. Без `key` пришлось бы
синхронизировать их вручную.

### Как работает приём сообщений

`ReceiveNotification` — long-polling: запрос висит до появления уведомления и возвращает пустой
ответ, если очередь пуста. Цикл в `useNotificationLoop` работает так:

1. Запрашивает очередь до появления уведомления.
2. Разбирает тело в событие (`parseWebhook`).
3. **Обязательно** подтверждает обработку через `DeleteNotification` — без этого уведомление
   вернётся в очередь снова и заблокирует её.
4. При сетевой ошибке повторяет запрос с нарастающей паузой (1, 2, 4, 8 … 30 секунд).

Очередь уведомлений общая для инстанса, поэтому её должен читать только один клиент —
при параллельном открытии страницы в двух вкладках сообщения будут распределяться между ними.

### Состояние сообщений

Отправленное сообщение появляется в ленте сразу (статус «часы»), затем статус уточняется
по уведомлению `outgoingMessageStatus`: `delivered` → `read`, либо `failed` с текстом
описания. Статусы не откатываются назад, дубликаты отсекаются по `idMessage`.

## Безопасность и ограничения прототипа

- `apiTokenInstance` хранится в `localStorage` и отправляется только на `api.green-api.com`.
  Для продакшена учётные данные нужно держать на сервере и проксировать запросы.
- GREEN-API не поддерживает CORS для всех хостов; `apiUrl` можно изменить в форме входа.
- Запросы идут напрямую из браузера, поэтому приложение нужно открывать по HTTPS.
- История чатов хранится локально и привязана к номеру инстанса.
